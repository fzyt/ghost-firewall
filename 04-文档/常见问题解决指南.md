## A. 网络连接问题

### A1: SSH 连接超时
**现象**: `ssh: connect to host 192.168.100.1 port 22: Connection timed out`

**可能原因**:
1. 路由器防火墙阻止了 SSH
2. 路由器未开机或网络不通
3. SSH 服务未运行

**解决方案**:
```bash
# 1. 检查网络连通性
ping 192.168.100.1

# 2. 检查 ARP 表
ip neigh show | grep 192.168.100.1

# 3. 检查 Web 服务是否可用（如果开启了反代）
curl -I http://192.168.100.1:5000

# 4. 如果 Web 服务可用，通过 API 检查状态
curl http://192.168.100.1:5000/api/status
```

### A2: Web 服务无法访问
**现象**: 浏览器无法打开 `http://192.168.100.1:5000`

**解决方案**:
```bash
# 1. 检查服务进程
ps w | grep "python3 app.py"

# 2. 检查端口监听
netstat -tlnp | grep :5000

# 3. 重启服务
cd /opt/nftables-web-v2/backend
pkill -f "python3 app.py"
python3 app.py &
```

## B. 防火墙规则问题

### B1: 规则应用失败
**现象**: nftables 规则未生效，或应用时报错

**解决方案**:
```bash
# 1. 检查当前规则
nft list ruleset

# 2. 检查规则文件
cat /etc/nftables.d/99-custom-rules.nft

# 3. 手动测试规则
nft -f /etc/nftables.d/99-custom-rules.nft

# 4. 查看系统日志
logread | grep nftables
```

### B2: 端口转发不生效
**现象**: 外网无法访问内网服务

**排查步骤**:
1. 检查规则是否生成
2. 检查目标服务是否运行
3. 检查网络连通性
4. 检查防火墙是否允许

## C. 反代服务问题

### C1: 大文件上传失败（413错误）
**现象**: 300MB+ 文件无法通过反代上传，小文件正常

**根本原因**: nginx `client_max_body_size` 限制

**解决方案**:
```bash
# 1. 修改反代配置
vi /etc/nginx/conf.d/fzyto.top-41825.conf

# 2. 在 location / 块中添加
location / {
    client_max_body_size 500M;  # 根据需求调整大小
    # ... 其他配置
}

# 3. 测试并重载配置
nginx -t
nginx -s reload
```

**优化配置**:
```nginx
location / {
    client_max_body_size 500M;
    proxy_buffering off;          # 禁用响应缓冲
    proxy_request_buffering off;  # 禁用请求缓冲（关键！）
    # ... 其他配置
}
```

**监控命令**:
```bash
# 监控临时目录使用情况
watch -n 1 'du -sh /var/lib/nginx/body; df -h /tmp'

# 监控内存使用
free -h
```

### C2: 反代登录态丢失（DSM）
**现象**: 通过反代访问 DSM 需要重复登录

**解决方案**:
```nginx
# 在反代配置中添加 cookie 域重写
proxy_cookie_domain ~^(\d+\.\d+\.\d+\.\d+) $host;
```

### C3: WebSocket 连接失败
**现象**: 需要 WebSocket 的应用无法正常工作

**解决方案**:
```nginx
# 在反代配置中添加 WebSocket 支持
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

## D. IPv6 相关问题

### D1: DDNS 报错 "No or private or invalid IP"
**现象**: DDNS 脚本报错，IPv6 地址更新失败

**根本原因**:
1. BUG1: 缩写 IPv6 地址处理失败
2. BUG2: 地址拼接产生无效地址
3. BUG3: 使用了 ULA（私有）地址

**错误地址示例**:
```
fdaa:9c8a:01d5:0000:0011:32ff:fe23:16c0  # ULA 地址，DDNS 拒绝
fdaa:9c8a:1d5:::1234:5678                # 无效地址（三冒号）
```

**临时解决方案**:
```bash
# 1. 禁用 DDNS 的 IPv6 更新
uci set ddns.1.use_ipv6='0'
uci commit ddns
/etc/init.d/ddns restart

# 2. 或修复 DDNS 地址文件
echo "240e:390:472e:4fe0::1" > /tmp/ddns-ipv6-1
```

**永久修复**: 需要修改 nftables-web 代码（见代码修复部分）

### D2: IPv6 端口转发失效
**现象**: IPv6 规则存在但流量不通

**排查步骤**:
```bash
# 1. 检查 nftables 集合
nft list set inet fw4 nas_ip6_1

# 2. 检查集合内容（应为空或包含正确地址）
nft list set inet fw4 nas_ip6_1

# 3. 检查 IPv6 地址获取
curl http://localhost:5000/api/network/wan-ipv6

# 4. 手动测试添加地址
nft add element inet fw4 nas_ip6_1 { 240e:390:472e:4fe0:0011:32ff:fe23:16c0 }
```

### D3: 公网 IPv6 未获取
**现象**: WAN 接口只有链路本地地址，没有公网 IPv6

**可能原因**:
1. ISP 未提供 IPv6
2. PPPoE 配置问题
3. DHCPv6 客户端故障

**排查步骤**:
```bash
# 1. 检查接口地址
ip -6 addr show pppoe-wan

# 2. 检查 DHCPv6 进程
ps w | grep odhcp6c

# 3. 检查网络配置
uci show network.wan6
uci show network.wan

# 4. 检查系统日志
logread | grep -i "odhcp6c\|dhcpv6\|ipv6"
```

## E. 系统配置问题

### E1: 存储空间不足
**现象**: 系统日志报磁盘空间不足

**OpenWrt 存储情况**:
```
内存: 1GB (通常足够)
/tmp: 500MB (tmpfs，内存文件系统)
/overlay: 87.4MB (系统盘，空间紧张)
```

**优化建议**:
1. 定期清理日志: `logread -c`
2. 避免在 `/overlay` 存储大文件
3. 使用 `/tmp` 作为临时目录
4. 监控命令: `df -h; du -sh /var/log/`

### E2: 服务自动重启失败
**现象**: 重启后服务未自动启动

**解决方案**:
```bash
# 1. 检查启动脚本
ls -la /etc/init.d/ | grep nftables-web

# 2. 启用开机自启
/etc/init.d/nftables-web enable

# 3. 手动启动
/etc/init.d/nftables-web start

# 4. 检查启动日志
logread | grep nftables-web
```

### E3: 证书过期
**现象**: HTTPS 访问报证书错误

**解决方案**:
```bash
# 1. 检查证书文件
ls -la /etc/nginx/ssl/fzyto.top/

# 2. 检查证书有效期
openssl x509 -in /etc/nginx/ssl/fzyto.top/fullchain.pem -noout -dates

# 3. 通过 nftables-web 界面更新证书
# 或手动更新证书文件
```

## 快速诊断命令

### 系统状态检查
```bash
# 1. 基础信息
uname -a
cat /etc/openwrt_release

# 2. 网络状态
ip -4 addr show
ip -6 addr show
ip route show
ip -6 route show

# 3. 服务状态
ps w | grep -E "nginx|python.*app|odhcp6c"
netstat -tlnp
```

### nftables 检查
```bash
# 1. 规则状态
nft list ruleset
nft list sets

# 2. 特定集合检查
nft list set inet fw4 nas_ip6_1
nft list set inet fw4 allowed4

# 3. 规则统计
nft list ruleset -a
```

### nginx 检查
```bash
# 1. 配置测试
nginx -t

# 2. 查看配置
nginx -T

# 3. 检查运行状态
nginx -s status

# 4. 查看编译配置
nginx -V
```

### 日志检查
```bash
# 1. 系统日志
logread
logread -f  # 实时查看

# 2. nginx 日志
tail -f /var/log/nginx/error.log

# 3. 应用日志
cd /opt/nftables-web-v2/backend
tail -f nohup.out  # 如果使用 nohup 运行
```
