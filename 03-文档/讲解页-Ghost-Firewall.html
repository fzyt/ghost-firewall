SECTION 01 / 06 · 问题

「把内网服务暴露到公网」
是一件天然危险的事

家里那台路由器上跑着 NAS、监控、测试环境。想让外面能访问，最直觉的做法是开端口转发 —— 于是每暴露一个服务，就多一个公网入口，每个入口都要自己记得加固。

入口散乱

一个服务一个端口

五个服务 = 五个公网端口。防火墙规则表越滚越长，没人敢删。

暴露面失控

面板也在公网上

管理面板和被管理的服务同样暴露 —— 攻击者拿到的是「改规则的权限」本身。

认证难做

每个服务各写一遍

要在每个服务前面加认证，工作量大且必然有遗漏 —— 漏掉的那个就是缺口。

解法

反过来：先收口，再认证

不给每个服务开端口，而是开一个。所有内网服务挂在这个端口的路径前缀下， 访问任何一条路径之前，流量先经过统一的认证 —— 认证只写一遍，缺口只有一个。

附带收益

面板彻底退出公网

认证通过之后连的是内网服务，公网上根本不需要存在管理面板。 面板只活在局域网里，攻击面从「整个规则系统」缩回「一个认证端点」。

SECTION 02 / 06 · 架构

三个入口，三种暴露面

刻意拆成三个进程、三个暴露面：面板管规则，网关管对外，认证后端只在环回口上。 点下面任意一张卡片，看它到底能被谁访问到。

入口 A

管理面板

https://<路由器IP>:5443
仅局域网可达

nftables 规则、反代配置、DDNS、日志、访问控制。

入口 B

认证网关

https://<域名或公网IP>:<自定义端口>/
可映射公网

公网唯一入口。按路径前缀把请求分发到不同内网服务。

入口 C

认证服务

127.0.0.1:8444
本机专属

网关的认证后端。公网侧永远看不到它。

管理面板 · 仅局域网

自签证书的 HTTPS 面板，是日常改规则的地方。 v0.8.0 起它只在局域网可达，公网侧不再有任何指向它的转发 —— 这意味着即使公网被扫到，也找不到能改防火墙规则的那个端口。

网关怎么判定放行？

nginx 的 auth_request 模块向认证服务发一个子请求， 用返回码决定放行与否。点击任意一种返回码看判定结果：

2xx
认证通过
放行，请求转发到内网服务
401
未认证 / 凭据无效
拒绝，跳转登录页
403
无权限
拒绝
500
认证服务自身出错
报错，同样不放行
2xx → 放行。nginx 拿到 2xx 才把请求转给内网服务。 
# 认证服务里最重要的一条硬规则（auth_gateway.py）
# nginx 的判定是：2xx 放行；401/403 拒绝；其他（500 等）报错，同样不放行。
# ⇒ verify 的任何异常路径都必须返回 401，绝不能漏出 5xx。

def verify():
    try:
        ...  # 正常校验
        return 200, ""
    except Exception:
        return 401, "unauthorized"   # 不是 500

SECTION 03 / 06 · 规则引擎

规则不是「拼出来的」，
是「模板 + 前导段」生成的

nftables 规则由 backend/templates/nftables.conf（578 行）渲染， 变量从面板的配置灌进去。但真正难的不是模板 —— 是模板前面那一段 preamble，它决定了「更新规则」会不会伤到系统里别人的东西。

坑 ①

表不存在时 flush 会报错

flush table inet fw4 在表不存在时报错。 首次部署时表还没建 → 直接炸。 

table inet fw4 { }
flush table inet fw4
坑 ②

table ip nat 是宿主机标准表

Docker / iptables-nft 的 dnat 和 masquerade 规则都住在里面。 flush table ip nat 会把它们一起清掉。

解法

只删自己那两条链

用 delete chain 而不是 flush chain —— 前者保留链对象和 hook 声明，后者会把 preamble 里的 hook 一起冲掉。 

delete chain ip nat prerouting
delete chain ip nat postrouting
设计原则

只覆盖，不删除

升级部署不碰配置、口令、密钥、限流表。规则集与 nginx 网关配置由面板运行时生成 —— 「换了代码 ≠ 生效」，必须重新生成规则。而每次生成都只重建本项目自己声明的那几条链， 宿主机上其他程序留下的痕迹一律不碰。

SECTION 05 / 06 · 安全设计

处理的是「谁能进你家路由器」，
所以取舍写得很死

口令

PBKDF2-HMAC-SHA256 / 200000 轮

标准库 hashlib 实现，不引第三方依赖。

进程边界

认证服务只监听 127.0.0.1

公网侧只有 nginx 一个入口，它必须先过认证。

文件权限

配置 640 root:nftweb / 密钥 600 root:root

且网关进程的 gid 必须等于配置文件的组 gid —— 读不到配置时网关会静默退回默认值而不报错，部署自检专门验这一条。

密钥不可变

替换前后比对 md5

不一致就大声报错 —— 密钥变了 = 所有设备的网关令牌全部作废 = 用户全部要重新登录。

数据安全

只覆盖，不删除

升级部署不碰配置、口令、密钥、限流表；失败自动回滚，不重启路由器。

前端

严格 CSP

前端不连任何外部域名 —— Alpine.js 与 Tailwind 全部随包分发，CSP 可以开得很死。

变异测试

故意改坏，看测试抓不抓得住

每个变异脚本注入一个缺陷（改条件、删校验、错 API 前缀……）， 确认对应测试会失败。测试没报错 = 这个测试没在测它该测的东西。 

# 全量回归（行为级 + 变异，零外部依赖）
bash tests/run_all.sh

# 真浏览器 e2e
bash tests/run_e2e.sh setup   # 装浏览器
bash tests/run_e2e.sh probe   # 14 页逐页枚举
bash tests/run_e2e.sh click   # 逐个点击，捕获 JS 异常与 4xx/5xx
bash tests/run_e2e.sh portal  # 认证门户全链路
点击权限

三档，默认最保守

--destructive 才点删除 / 清空 / 应用规则； --allow-network 才点重启网络 / 切 PPPoE。 最后一档会直接把网络搞挂 —— 开之前务必确认有一条带外恢复通道。
