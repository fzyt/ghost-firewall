# Alpine 3 求值语义：模板表达式「以 if 开头」的静默陷阱

> 记录日期：2026-11-10
> 起因：系统信息页数据面扩充（v0.19.8）时，接口明细方法起名 `ifaceDetail(iface)`，
> 页面上那一行**永远是空的**，但所有测试全绿、不报错、不白屏。
>
> 这份记录的目的是**留下可复用的判据**，而不是记流水账。
> 本条知识跨项目可复用（任何用 Alpine 的前端都适用），
> 但按项目纪律**不写入 Hindsight 记忆库**（用户红线），落在这里。

## 证据等级约定

| 标记 | 含义 |
|---|---|
| `[实证]` | 在真机 / 真实浏览器里实测复现过 |
| `[源码]` | Alpine 压缩源码里可直接读到的实现 |
| `[推断]` | 合理推论，未实测 |

## 一、现象

```js
// app.js
detailOf(iface) { ... }        // ← 方法名以字母 "if" 开头
```
```html
<!-- index.html -->
<div x-text="detailOf(iface)"></div>
```

页面上的这一格**永远是空的**。

| 观察 | 结果 |
|---|---|
| 页面报错 | **没有** |
| 白屏 | **没有** |
| 浏览器控制台 | **干净** |
| 页面其它部分 | **完全正常** |
| 其它测试 | **全绿**（v0.19.8 契约 64 + 渲染 64 + 变异 36 条全捕获） |

最要命的一条：**「空」本身就是这一格的合法状态**（设计如此：读不到的字段就不显示，
不堆「未知」）。所以这一格空着，肉眼扫过去根本发现不了 ——
除非有人正好在查「这格为什么没内容」。

## 二、根因 `[源码]`

Alpine 3.15.8 的求值器（`frontend/assets/alpine.js` 的 `generateEvaluatorFromString`，
压缩后叫 `Jn`）：

```js
n = /^[\n\s]*if.*\(.*\)/.test(t.trim()) || /^(let|const)\s/.test(t.trim())
    ? `(async()=>{ ${t} })()` : t
// ...
new AsyncFunction(['__self','scope'],
  `with (scope) { __self.result = ${n} }; __self.finished = true; return __self.result;`)
```

两个要点：

1. **正则没有词边界** ⇒ `ifaceDetail(iface)` 这种「以 if 打头的方法名」一样中招；
2. 被包成 `(async()=>{ ... })()` 之后，**块体里的表达式值被丢弃**
   （async IIFE 的块体没有 `return`）⇒ `__self.result` 拿到 `undefined`
   ⇒ `x-text` 渲染成空。

## 三、⚠️ 最关键的一条：同一条正则，两类位置语义相反

这是第一版判据**报错的地方** —— 也是最容易踩的认知坑。

| 位置 | Alpine 走的求值器 | 以 `if` 开头 + 带括号 | 后果 |
|---|---|---|---|
| **值位**<br>`x-text` / `x-html` / `:class` / `:style` / `:disabled` / `:value` / `:key` / `:title` / `:type` / `:placeholder` / `x-show` / `x-if` / `x-model` / `x-bind:*` / `x-for` 的 **items** 部分 | `Jn`：`(async()=>{...})()` | **值被丢弃** | 页面显示空白 —— **致命** |
| **副作用位**<br>`@click` / `@change` / `@input` / `@submit` / `@keydown` / `x-on:*` / `x-init` | `xr`：`(()=>{...})()` | 副作用正常执行 | **Alpine 官方推荐写法** |
| **字面量位**<br>`x-transition:enter*` / `x-ref` / `x-cloak` | 不求值 | 不适用 | 不适用 |

也就是说 `@click="if(confirm('确定退出登录？')) doLogout()"`
**本来就是对的**（Alpine 文档推荐写法），把它当 bug 去改反而是画蛇添足。

`let` / `const` 同理，但注意 Alpine 的正则要求 `let` / `const` 后面**有空白**
（`/^(let|const)\s/`）⇒ 方法名 `letThing(v)` **安全**，`let x = 1` 才中招。

### 实测依据 `[实证]`

浏览器探针：`tmp/alpine-probe.js` / `alpine-probe2.js` / `alpine-probe3.js`
（把真的 `alpine.js` 塞进 Chromium 逐项试）：

| 探针 | 结果 |
|---|---|
| `x-text="ifDetail(v)"` | 渲染成 **空** |
| `x-text="okDetail(v)"` | 正常显示 |
| `x-text="letThing(v)"` | 正常显示（`let` 后无空白，不中招） |
| `x-show="ifDetail(v)"` | **隐藏**（值 undefined ⇒ falsy） |
| `x-if="ifDetail(v)"` | **不渲染** |
| `x-for="(i,idx) in ifList.filter(x => x > 7)"` | **0 项**（items 那半中招） |
| `x-for="(i,idx) in ifList"` | 3 项（没括号，正则要求括号） |
| `@click="if (v > 1) act()"` | 副作用**正常执行**（hit 计数 +1） |
| `x-init="if (v > 1) initFn()"` | 副作用**正常执行** |
| `x-transition:enter="__UNDEF__"` | 不报错 ⇒ **字面量位** |
| `x-ref="__UNDEF__"` | 不报错 ⇒ **字面量位** |

## 四、为什么已有测试全绿

所有文本层面的测试用的都是**自己的求值器**（`new Function`），
那是普通 JS 表达式语义，跟 Alpine 的行为**不是一回事**。

⇒ 「测试全绿」根本不能证明 Alpine 页面是对的。
必须有一个判据**用 Alpine 自己的规则**去检查模板。

## 五、判据的四条设计约束

判据落在 `tests/test_frontend_alpine_expr.js`（28 项），
配套变异脚本 `tests/mutation_check_alpine_expr.py`（6 条）。

### 1. 正则必须从 `alpine.js` 里抽出来，不能手抄

手抄的会和 Alpine 实际行为脱节 —— 那比没有判据更坏
（它会给人「已经验过了」的错觉，而实际没验过）。

抽取点**锚定在 Alpine 的值位求值路径**上（`__self.result = ` 这个全文件唯一的标记）：

```js
const VALUE_PATH_ANCHOR = '__self.result = ';
const win = ALPINE_JS.slice(anchor - 800, anchor);
const detectors = [...win.matchAll(/\/\^[^/]*\/[a-z]*\.test\(/g)];
```

⚠️ **不能**「扫全文件取唯一字面量」—— 第一版就是这么写的，被自己的变异脚本抓出漏洞：
把值位路径那条换成宽松版，全文件**还有另一条一样的旧正则**
⇒ 判据照样抽得到、照样全绿 ⇒ **判据默默接受了错误的行为**。

⇒ 所以除了抽取，还要断言「全文件所有 detector 都是同一条」（实现未分叉）。

### 2. 按位置语义分类，不能一锅端

值位必查 / 副作用位豁免 / 字面量位不管；
模板里出现**归不出来的属性**直接判失败（不许默默放过新属性）。

### 3. 判据要比被测对象更强

不只查「模板里现在有没有踩坑」，还查 `app.js` 里的**方法名**：
将来任何人写 `x-text="ifaceDetail(x)"` 都会中招，所以要在方法定义处就拦住。

⚠️ 提取方法名必须避开 **JS 语句**：
`/^\s{4}([A-Za-z_$][\w$]*)\s*\([^)]*\)\s*\{/` 会把 app.js 里
`if (this.ddns.editingIsNew) {` 这种**语句**当成方法名（`\s` 含换行，跨行匹配），
第一版就误报了 6 个 "if"。

⇒ 修法：行首锚定 + 排除 JS 关键字。

### 4. 求值装置不能掩盖真实缺陷

两个真实踩过的例子：

| 装置缺陷 | 后果 |
|---|---|
| 渲染测试里方法名清单**写死** `['fmtRate', 'detailOf', ...]` | 方法一改名，scope 里就少它 ⇒ 报 "X is not defined" ⇒ **把真正该报的诊断盖掉** |
| 渲染脚本里选择明细格的 CSS **写死方法名** | 退化时报「选择器失效」而不是「值被丢掉」⇒ **假捕获** |

⇒ 修法：清单从模板**动态提取**；选择器按**位置**找（接口名那一格右边的 text-xs 块），不按方法名找。

## 六、怎么把「Alpine 语义」搬进没有浏览器的回归

`tests/test_frontend_system_info_render.js` 的「第 1b 组」用**照抄 Alpine 的包装逻辑**
再求值一遍（正则同样从 alpine.js 抽）：

```js
const wrapped = ifRe.test(t) || declRe.test(t);
const body = wrapped ? `(async()=>{ ${t} })()` : t;
const fn = new AsyncFunction(['__self', 'scope'],
  `with (scope) { __self.result = ${body} }; ` +
  `__self.finished = true; return __self.result;`);
```

这样即使没有浏览器也能复现 Alpine 的真实行为：
方法改名回 `ifaceDetail` ⇒ 这组**精确地**报出
「用 Alpine 语义重算，没有表达式取值被丢弃（页面不会显示空白）— ifaceDetail(iface)」。

## 八、本轮在变异脚本上真漏过 3 次（都写进了代码注释）

1. 判据第一版把 `@click="if(confirm(...))"` 也当 bug
   ⇒ **判据写宽了**，不是代码有坑（教训：先分清位置语义）
2. 方法名正则把 `if (...) {` **语句**当成方法名（`\s` 含换行，跨行匹配）
   ⇒ 误报 6 个 "if"
3. A2 变异一开始用的是**模板里没有的新属性**（`x-data-x`），
   结果它是被「属性分类完备性」那条**兜底**抓住的，不是被值位检查本身抓住的
   ⇒ 兜底能兜住只是一次运气 ⇒ 改成落在**已知值位属性**（`x-text`）上

⇒ 教训仍然是那条老规矩：**样本必须落在判据真正生效的那条路径上**，
「测试通过」不等于「判据被验证过」。
