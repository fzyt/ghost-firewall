# 面板极简模式开关：磨砂、动效、像素场全不要（2026-11-17）

对象：`.193`（192.168.100.193，面板 5443）
证据等级：`[实证]` = 真机实测有输出佐证；`[固定]` = 代码/设计已定；`[待确认]` = 需要复现验证。

## 一、用户诉求与实测依据

用户原话：「5443 的页面动效有点太足了，磨砂什么的都不要了把」
以及一个问句：「目前页面渲染是不是磨砂占用了主要的性能消耗？」

### 1.1 那个问句的答案：不是主要 CPU 开销，但它是**帧率**杀手 `[实证]`

四组 A/B（headless Chromium + SwiftShader 软件光栅，登录页 1600×1000，6 秒采样）：

| 配置 | FPS | 脚本耗时 | 任务耗时 |
|---|---|---|---|
| A 基线（全开） | **7.8** | 1.109s | 1.227s |
| B 只去磨砂 | **54.8** | 4.644s | 5.247s |
| C 只去像素场 | **7.8** | 0.001s | 0.045s |
| D 两个都去 | **60.2** | 0.009s | 0.300s |

读法：

- **帧率**：A 和 C 都是 7.8（像素场在不在不影响帧率），B 和 D 都上 55~60
  ⇒ **磨砂决定帧率**。
- **CPU**：像素场在 → 每 6 秒烧 1.1 秒纯 JS；像素场不在 → 脚本耗时归零
  ⇒ **像素场决定 CPU 占用**。
- B 组脚本耗时反而变大不是矛盾：磨砂一去掉帧率上去了，像素场终于能跑满 60fps，
  每帧约 14ms × 60 ≈ 0.84s/秒，累积就上去了。

⚠️ **这个测量的限制必须说清楚**：headless 没有 GPU，磨砂走 CPU 软件光栅，
**绝对数字被夸大了**。真机浏览器里磨砂是 GPU 合成，通常便宜得多。
像素场那 14ms/帧是纯 JS，不受 GPU 影响，这个数字可靠。

## 二、方案 `[固定]`

用户补充要求：「设计一个开关吧，这个开关可以缓存，切换后动画、磨砂都没有了，
就是最简单元素的页面」＋「开关打开后，全停」。

⇒ 做一个**能记住的开关**，打开后：磨砂、动效、像素场、连无限循环动画一起停，
页面只剩最简元素。

### 2.1 状态存哪：浏览器本地（localStorage）

这是**观感偏好**，不是设备状态。存服务端要动共享配置、要加接口、多设备还得同步 ——
为一个开关不值得。`localStorage['nf_plain_mode']`（`'1'` = 开）。

代价要说清楚：**换浏览器/换设备不跟随**。观感偏好就该这样。

### 2.2 首屏不能闪

极简模式的用户每次打开面板，**不能先看到一帧动效再卡住**。

⇒ 开关脚本必须**同步加载**且排在 `styles.css` **之前**：
浏览器解析到 `<script>` 就执行，`<html>` 上的 class 在样式生效前就位。

塞进 `defer` 脚本就晚了（defer 要等 HTML 解析完），会闪。

### 2.3 像素场：**不挂载**，不是「藏起来」

这是本批最要紧的一条。`display:none` 的画布，rAF 照样跑，
每帧照样 `putImageData`（实测每帧约 14ms JS）—— **CPU 一分都不省**。

⇒ 极简模式下**压根不调用** `GhostPixelField.createStyle()`。

### 2.4 用 `duration` 而不是 `none`

`transition: none` 会让 `transitionend` **永远不触发** ⇒ Alpine 的 `x-transition`
以为过渡没结束，元素卡在起始态（`opacity:0`）＝ **看不见**。

⇒ 沿用本文件里 `prefers-reduced-motion` 已有的做法：时长压到 `.001ms`、
`animation-iteration-count: 1`。事件照常触发，视觉上就是瞬切。

## 三、代码改动

| 文件 | 改动 |
|---|---|
| `frontend/plainmode.js`（**新增**） | 开关本体：读/写 localStorage、摆 `<html>` 上的 class、通知像素场 |
| `frontend/pixelbg.js` | 极简模式**不挂载**引擎；暴露 `apply(on)` 供切换时停/起 |
| `frontend/styles.css` | `html.nf-plain` 规则块（磨砂关、动效压到 .001ms）+ 开关样式 |
| `frontend/index.html` | head 里同步引入 `plainmode.js`（排在样式前）；侧栏底部加开关 |
| `frontend/app.js` | `plainMode` 状态 + 初始化同步 + `setPlainMode()` |
| `backend/app.py` | **未改**（静态服务按扩展名白名单放行 `.js`，从 `frontend/` 取） |

### 3.1 切回普通时的次序（容易错的地方）

`applyPlain(false)` 里**先让画布可见再挂引擎** ——
`display:none` 的画布量不到尺寸，引擎会按 0×0 初始化，显示出来是一片空。

### 3.2 首屏就是极简时切回普通

首屏极简 ⇒ 引擎从没挂载过 ⇒ 切回普通时**这时才第一次挂**（判据 PM-5 守着这条）。

### 4.1 行为判据（node，真跑脚本）

把 `plainmode.js` 与 `pixelbg.js` 塞进 vm 沙箱真跑，桩掉 `localStorage`/`document`：

- **PM-1** 首屏同步生效（存着开启 ⇒ `<html>` 立刻带 `nf-plain`）
- **PM-2** 开关能切、且记住（反复切都灵）
- **PM-3** localStorage 不可用（隐私模式）时不崩，且本次会话仍生效
- **PM-4** 极简模式下**引擎一次都没被调用**（藏起来不算）
- **PM-5** 切换时引擎跟着停 / 起；首屏极简时切回普通才第一次挂
- **PM-6** 开关通知得到像素场；像素场还没就绪时切开关不抛异常

### 4.2 接线判据（python）

- **PM-W1** index.html：脚本**同步**（无 defer）且排在 `styles.css` 之前；开关 UI 在
- **PM-W2** styles.css：规则块存在、磨砂关掉、动效压到 `.001ms`、**没有**用 `transition: none`
- **PM-W3** app.js：状态字段、`setPlainMode`、初始化同步、切换转发
- **PM-W4** pixelbg.js：`plainOn()`、`applyPlain()`、挂载前先问、暴露 `apply`
- **PM-W5** 后端：静态白名单含 `js`（否则 `/plainmode.js` 会 404）、静态服务从 `frontend/` 取

⚠️ 「不该出现」类断言用**去注释版**源码 ——
`styles.css` 的注释里就写着 `transition: none`（解释为什么不能这么写），不去注释会自己骂自己。

### 4.3 变异覆盖的失败模式

开关的失败模式全是「**看起来还在、其实已经不生效**」：

- 切了不记住 / 记住了不生效 / 只加不删 class
- 存不了时崩、读不了时崩
- **极简模式照样挂载像素场 / 只藏画布不停引擎**
- 切换时不停引擎、不恢复引擎、不把画布显示回来
- 磨砂关一半、动画时长没压、无限循环没停、用 `transition: none`
- 脚本 defer / 排在样式后 / 开关 UI 没了
- 勾选框不初始化 / 点了没反应 / 状态字段没了
- 后端白名单去掉 `js` ⇒ 新文件 404

## 六、已知限制与待做

### 6.1 开关只在登录后的侧栏底部 `[固定]`

未登录时侧栏被 `x-show` 藏着 ⇒ **登录页上找不到这个开关**。
但登录页本身会跟着走（`html.nf-plain` 作用在整棵树）：
已开极简模式时，登录页也是无磨砂、无像素场的。

⇒ 想在登录前就切，得再加一个登录页上的入口（本次没做，用户没要求）。

### 6.2 换设备不跟随 `[固定]`

见 2.1。观感偏好，存在浏览器本地。

### 6.3 加载指示器（spinner）也会停 `[固定]`

`nf-spin` 同样是无限动画 ⇒ 极简模式下只转一次就停。
用户要的是「全停」，这是符合要求的取舍。

### 6.4 headless 测出来的磨砂成本偏大 `[待确认]`

见 1.1 的警告。**真机带 GPU 的浏览器里，磨砂到底占多少没测过**
（手边没有能开 DevTools 的桌面浏览器环境）。
⇒ 「极简模式能提升多少帧率」这个数字，在真机上应当比 6.4→60.2 小得多，
但**方向**是确定的（磨砂在软件光栅下就是压帧率的那个）。

### 6.5 门户（8443）没动 `[固定]`

用户只说 5443。门户是 `backend/static/` 下另一套页面与样式，
`pixelfield.js` 是两边共用的引擎源码 —— 本次**没有改引擎**，
只改了面板自己的 `pixelbg.js`（引导层）与 `styles.css`。
