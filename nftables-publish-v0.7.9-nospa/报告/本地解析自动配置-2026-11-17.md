对象：`.193`（192.168.100.193，OpenWrt 25.12.5 r33051-f5dae5ece4，Linux 6.12.94）
关联：接口名钉定见《接口名漂移根因与钉名方案-2026-11-15.md》；
多 LAN 口见《多LAN口面板写入-2026-11-15.md》

证据等级：`[实证]` = 真机实测有输出佐证；`[固定]` = 代码/设计已定；`[待确认]` = 需要复现验证。

## 一、这功能解决什么

面板的 host 分发入口挂的是**域名**（本机是 `siyuan.fzyto.top`）。
内网客户端拿这个域名访问时：

- 公网 DNS 把它指到公网 IP ⇒ 报文出不去（NAT 回环通常不通），或者落到别的机器上；
- 就算绕出去了，回来时源地址是公网 IP，和证书里的域名对不上。

⇒ 让**路由器自己的 dnsmasq** 把这个域名（及其所有子域）直接答成本机 LAN IP。
内网客户端一解析就落在本机，不依赖公网 DNS、不依赖 NAT 回环。

**自动**的意思：用户在面板里换了证书/基础域名 ⇒ 解析记录跟着走，
不需要用户自己去 SSH 里敲 `uci add_list`。

## 二、机制：`[实证]`

### 2.1 写在哪个配置里

OpenWrt 的 dnsmasq init 脚本是**每个 `config dnsmasq` 段起一个独立实例**，
每个实例一个配置文件 `/var/etc/dnsmasq.conf.<段名>`。

`.193` 实测：

```
/etc/config/dhcp              →  uci show dhcp 显示成 dhcp.@dnsmasq[0]=dnsmasq（匿名段）
/var/etc/dnsmasq.conf.cfg01411c  →  真正在跑的那个实例的配置文件
```

**⚠️ 绝对不能新建 `config dnsmasq` 段** —— 新段会变成第二个实例，
端口 53 抢不到就起不来。实测（本次手工实验，2026-11-17 00:30）：

```
procd: Instance dnsmasq::nftweb_local_domain s in a crash loop 6 crashes, 0 seconds since last crash
```

⇒ 本功能**只往默认实例（匿名段）里加 list**，绝不新建段。

### 2.2 本地解析怎么写

正确写法是**域名形式**的 `list address`：

```
list address '/siyuan.fzyto.top/192.168.100.193'
```

init 脚本生成：

```
address=/siyuan.fzyto.top/192.168.100.193
```

`--address` 是**域名形式** ⇒ 覆盖该域名**及其所有子域**。
实测 `siyuan.fzyto.top` 和 `abc.siyuan.fzyto.top` 都答 `192.168.100.193`。

为什么必须是域名形式：泛域名证书的 host 分发入口通常挂在**子域**上
（`abc.siyuan.fzyto.top`），精确的 `config host` 只覆盖 apex。

### 2.3 「这条是本面板写的」怎么认

用一个标记 option：

```
option nftweb_local_domain 'siyuan.fzyto.top'
```

实测 **dnsmasq 完全忽略它**（生成的配置文件里 0 次出现，只有 `enable-ubus=` 那行是实例名，
不是这个 option）—— 但 `uci get` 能读回来。

⇒ 用它认「哪条 address 是本面板写的」，
**用户自己手写的 `list address` 一律不动**（这是本功能最容易闯祸的地方：
一把 `uci set` 覆盖整个列表，用户自己的解析就没了）。

### 2.4 uci 的两个坑

| 坑 | 实测行为 | 本功能怎么绕 |
|---|---|---|
| `uci get` 读列表 | 返回**空格分隔的一行**，不是每行一个 | 按空格切 |
| `uci del_list` 删不存在的值 | rc≠0（`Entry not found`） | 先比对再删，只删确实在列表里的值 |

### 2.5 域名规范化

域名会**原样**进 dnsmasq 的 `--address=` ⇒ 带斜杠/空格/换行都会改变解析结果。
写入前统一：转小写、去结尾的点（`EXAMPLE.COM.` → `example.com`）。
不这么做，`EXAMPLE.COM` 和 `example.com` 会变成两条不同记录。

## 三、实现

### 3.1 `backend/dhcp_hosts.py`（新增）

| 函数 | 作用 |
|---|---|
| `_dnsmasq_section()` | 找到默认 dnsmasq 段的寻址串（`@dnsmasq[0]` 或具名段） |
| `_address_domain(entry)` | 从 `/domain/ip` 里取域名部分 |
| `_uci_list(section, key)` | 读列表选项的全部值（按空格切） |
| `_validate_local_domain(domain)` | 域名格式校验 |
| `_validate_local_ip(ip)` | IPv4 格式校验 |
| `set_local_domain_resolution(domain, ip)` | 主入口：增删本面板的那条记录 |

主入口完全复用本模块既有的写盘骨架：`_write_lock` → `_make_backup` → 写 →
`_check_syntax` → 失败则 `_discard_pending` + `_restore` → 成功才 `reload_dnsmasq`。

**domain 为空 ⇒ 删掉本面板写的那条**（证书换掉了 / 不再用泛域名）。
但**标记 option 不删** —— 留着它，下次域名又变回同一个时那条记录仍旧认得出来是「我们的」。

### 3.2 `backend/app.py`（新增）

`_sync_local_domain_resolution(config, lan_ip=None)`：

- 域名取 `_rp_base_domain(config)`（用户填的值优先，否则从默认证书 SAN 推导）；
- IP 取**内核此刻实际持有的** LAN 地址（`_lan_bind_address()` 探测），
  **不取配置里的旧值** —— `router_ip4` 可能是过期的 DHCP 租约；
- 失败只返回 `{'ok': False, ...}` 并打 `[WARN]`，**不抛异常、不挡配置落盘**
  —— DNS 解析写不进去不该让整个保存动作失败。

三个触发点：

| 位置 | 时机 | 为什么在这儿 |
|---|---|---|
| `app.py:10115` `_save_rp_config()` | 每次保存反代配置 | 换证书/改域名都在这条路径上 |
| `app.py:15110` 启动段 | 面板服务启动 | 重装/升级/重启后自动补回记录 |
| `app.py:4628` `/api/network/restart` | 网络重启之后 | 断网重启可能换租 ⇒ IP 得跟着改 |

### 3.3 `tests/fixtures/fake_uci.py`（改）

原来的桩**直接把 `list` 行丢掉** —— 对 uci 的保真度有缺口，
新功能要测的恰恰就是 list 的增删。补了：

- `add_list` / `del_list` 子命令；
- `load()` 解析 `list` 行、`dump()` 按 list 写回；
- `get`/`show` 对列表输出**空格分隔一行**（与真 uci 一致）；
- `find_section` 支持 `@type[idx]`；
- `ident` 改成按**类型内序号**；
- `FAKE_UCI_CORRUPT_COMMIT=1` 开关（整个文件写坏，模拟 commit 写坏）。

### 4.1 顺带挖出来的一个坑：变异锚点失效 `[实证]`

这一批第一次跑全量回归时，`mutation_check_c_batch.py` 挂了（rc=1）。
查下来**不是**这批功能写坏了，而是**这批功能把别人的守门锚点顶掉了**：

- C-02 那条变异守的是「`router_ip4` 自愈必须**紧挨** `_ensure_https_cert()`」
  （证书 CN 用的是 router_ip4，顺序反了证书就停在旧 IP 上）；
- 它的锚点是一段**跨块**的连续文本（从 `try:` 一直到 `cert_files = ...`）；
- 本地解析的启动钩子正好插在这两块**中间** ⇒ 锚点 0 次命中
  ⇒ 那条变异被判「脚本自身的错」⇒ 计入漏网 ⇒ 整个脚本 rc=1。

⇒ **表现是「这条变异没被抓住」，实际上是「这条变异压根没跑过」** ——
守门形同虚设。而这类问题**要跑满一小时的全量回归才看得见**。

修法：**把新代码挪出那个间隙**（挪到 `router_ip4` 自愈之前），
并写了个注释说明「这两块之间的相邻关系是被变异脚本守着的，别往中间插东西」。

同类的坑本项目已经栽过两次（前一次是 `mutation_check_setup_resume.py`
的 M15 锚点，2026-11-16 修）⇒ 顺手加了一个判据把这类问题挡在前面：

**`tests/test_mutation_anchors.py`** —— 静态扫描全部 62 个变异脚本，
把它们用的 (old, new) 二元组里的 **old 侧**拿出来，
逐条到源码里找（先找该脚本自己声明要改的文件，再兜底扫
`backend/` `frontend/` `setup/` `tools/`）：

- 找得到 → `[PASS]`
- 找不到 → `[FAIL]`，并打印失效的锚点原文

跑一次 **0.27 秒**（对比全量回归的一小时）。
双向验证过：把 bug 装回去 ⇒ 判据 rc=1 并点名 C-02 那条锚点；
装回修复版 ⇒ 62/62 通过。

⚠️ 这个判据读的是**工作区** ⇒ 变异脚本运行期间跑它会误报
（那时源码正被临时改写）。全量回归里它在变异阶段之前跑，不会撞上。

## 六、踩过的坑

### 6.1 测量坑（不是功能坑）

| 坑 | 现象 | 教训 |
|---|---|---|
| nslookup 输出解析 | 输出里第一行 `Address: 127.0.0.1#53` 是**服务器**地址，直接抓第一个会把它当答案 | 要按 `Name:` 定位下一行 |
| procd 异步启动 | `/etc/init.d/dnsmasq restart` 返回后 dnsmasq 要 **1~3 秒**才开始监听，立刻 nslookup 得到空 | 重启后解析类检查必须轮询重试 |
| 手工实验的残留 | 之前「新建 `config dnsmasq` 段」的实验在 `/var/etc/` 留了一个孤儿配置文件 + 一个崩溃循环的 procd 实例 | 实验完要确认 `/var/etc/dnsmasq.conf.*` 和 procd 实例都干净（本次已清理，残留文件归档到 `/root/dnsmasq.conf.nftweb_local_domain.stale-20261117`） |

### 6.2 工程坑：把别人的守门锚点顶掉了

见 4.1 —— 启动钩子插在「router_ip4 自愈」与「`_ensure_https_cert()`」之间，
破坏了 C-02 变异依赖的**相邻关系** ⇒ 锚点失配 ⇒ 那条变异压根没跑。

教训：**往已有代码中间插东西之前，先确认有没有变异脚本靠「相邻关系」守着**。
现在有 `tests/test_mutation_anchors.py` 兜着（0.27 秒出结果）。

### 6.3 顺序坑：钩子先于落盘

`_save_rp_config()` 里本地解析钩子跑在 `save_config()` **之前**。
⇒ 极端情况下（配置写盘失败），DNS 记录会短暂领先于已保存的配置。
影响很小且自愈（下次保存或重启即纠正），故未调整顺序。

## 七、已知限制与待做

### 7.1 `/api/network/restart` 未做真机端到端 `[待确认]`

`.193` 的 `br-lan` 是 **DHCP**（`network.lan.proto='dhcp'`），
真调这个接口有可能换租 ⇒ SSH 失联、设备找不回来 ⇒ **没有实测**。

它调用的正是 5.4 里验证过的同一个 `_sync_local_domain_resolution()`，
逻辑上覆盖；差的是「网络重启本身会不会换 IP」这一步没在真机上跑过。

### 7.2 面板上没有可见的入口 `[固定]`

本地解析是**跟随基础域名自动生效**的，面板上没有「查看/删除本地解析」的按钮。
用户自己写的 `list address` 面板也看不到。
⇒ 想查当前记录，只能 SSH 看 `uci show dhcp`。

### 7.3 只覆盖「基础域名 + 其子域」 `[固定]`

用户手动填在 settings 里的 `base_domain` 与证书实际 SAN 不一致时，
本地解析跟着 `base_domain` 走（与 host 分发入口保持一致），
但此时证书和域名本来就对不上 —— 那是另一个问题。

### 7.4 宿主 DNS 的缓存 `[待确认]`

客户端拿到 192.168.100.193 之前，若已缓存过公网解析，会按 TTL 继续用旧值。
本功能不负责清客户端缓存（也不该清）。
