## 2. 装机失败与根因

### 2.1 现象

`tools/deploy.sh --host 192.168.100.120` 走全新安装路径，卡在【依赖安装】阶段：

```
[ERROR] nginx 未安装成功 —— 网关无法工作，请检查网络后重试
```

日志里每个镜像都报同一句：

```
WARNING: updating and opening https://mirrors.ustc.edu.cn/.../packages.adb: unexpected end of file
ERROR: wget: exited with error 8
ERROR: unable to select packages: wget-ssl (no such package)
```

三个候选镜像轮了一圈，全部失败，最后 nginx 没装上。

### 2.2 根因：**switch_apk_mirror 只换主机、没换路径前缀**

国内镜像的 OpenWrt 仓库挂在 `/openwrt/` 下面，比官方源**多一层**：

```
官方源  https://downloads.openwrt.org/releases/25.12.5/...
国内源  https://mirrors.ustc.edu.cn/openwrt/releases/25.12.5/...
```

而 `setup.sh` 的 `switch_apk_mirror` 只把 URL 里的主机名换掉、**路径原样保留** ⇒ 切过去的 URL 变成：

```
https://mirrors.ustc.edu.cn/releases/25.12.5/...     ← 三个国内镜像上全是 404
```

开发机 curl 实测（三个 host × 两种前缀全测过）：

| URL | 状态码 |
|---|---|
| `https://mirrors.ustc.edu.cn/releases/25.12.5/packages/x86_64/base/packages.adb` | **404** |
| `https://mirrors.ustc.edu.cn/openwrt/releases/25.12.5/packages/x86_64/base/packages.adb` | **200** |
| `https://mirror.nju.edu.cn/openwrt/releases/25.12.5/packages/x86_64/base/packages.adb` | **200** |
| `https://mirrors.tuna.tsinghua.edu.cn/openwrt/releases/25.12.5/packages/x86_64/base/packages.adb` | **200** |

### 2.3 为什么这个 bug 特别难查

**症状和「官方源被截断」一模一样。**

setup.sh 的注释里就写着「官方源在国内网络大文件会截断」，所以看到
`unexpected end of file` 一定会往截断方向想。但真实原因是 **404** ——
404 的响应体不是索引文件，apk 也报成 end of file。

而且这是**救急动作本身把能用的源弄坏了**：官方源本来是好的
（.120 上首次 `apk update` 成功，11258 个包可用），切镜像之后反而全挂。

### 2.4 排除的其他可能

| 怀疑 | 实测 | 结论 |
|---|---|---|
| 磁盘满 | overlay 剩 38.2 MB / 86.4 MB | 排除 |
| IPv6 优先导致下载异常 | `wget -4` 强制 IPv4 仍 404 | 排除 |
| 网络不通 | `wget https://mirrors.ustc.edu.cn/` 根路径 200 | 排除 |
| wget 坏掉 | busybox `uclient-fetch`，https 可用 | 排除 |
| 包源清单为空 | `/etc/apk/repositories.d/distfeeds.list` 有 8 行正常条目 | 排除 |

## 3. 修复

### 3.1 代码改动（`setup/setup.sh` 的 `switch_apk_mirror`）

原来：

```sh
sed "s#://[^/]*/#://${host}/#" "$repo" > "$tmp"
```

改成（一条 sed 同时换主机 + 统一路径前缀）：

```sh
sed "s#^\(https\{0,1\}://\)[^/]*/\(openwrt/\)\?releases/#\1${host}/openwrt/releases/#" \
    "$repo" > "$tmp"
```

要点：

- `(openwrt/\)\?` 是**可选组** —— `apk_update_with_failover` 会依次试多个镜像，
  第二次调用时文件里**已经带 openwrt/ 了**。可选组让「已带」和「没带」
  两种输入收敛到同一结果 ⇒ **幂等**。
- 用 `\{0,1\}` 而不是 `\?` —— busybox sed 对 `\?` 的支持随版本不同，
  `\{0,1\}` 是 BRE 里到处都支持的那种写法。

### 3.2 判据（`tests/test_setup_apk_fallback.py` 新增第 5 节）

**行为级**断言：沙箱里造一份和 .120 真机一致的 distfeeds.list，**真跑**
`switch_apk_mirror`，检查产物路径形态：

- 每行必须是 `<host>/openwrt/releases/` 形态
- 不能有漏掉 `openwrt/` 层的行
- 不能出现 `openwrt/openwrt/` 双层
- 连切两次后形态仍然正确（幂等）

另在 `tests/test_setup_resume.py` 里把**原来那条错误的静态断言**改掉 ——
它原来断言「换源只替换 URL 的主机部分（路径不动）」，
理由是「只换 host ⇒ 不依赖 OpenWrt 的仓库布局」，而 .120 实测证伪了这个假设。

### 3.3 判据有效性验证（变异测试）

把 `switch_apk_mirror` 改回旧写法（只换主机）后：

| 测试 | 结果 |
|---|---|
| `test_setup_apk_fallback.py` | **3 项失败，rc=1** |
| `test_setup_resume.py` | **1 项失败，rc=1** |

两个测试都精确捕获了这个变异。

### 3.4 真机验证（busybox sed）

修复后的 sed 表达式在 **.120 的 busybox sed** 上真跑：

```
[PASS] 切到 mirrors.ustc.edu.cn：全部行都是 mirrors.ustc.edu.cn/openwrt/releases/ 形态
```

## 6. 遗留与提醒

1. **磁盘余量 31.8 MB**（86.4 MB 的 overlay）。再装大包前先 `df -h /overlay`。
2. **面板密码**是本次装机时新设的（与 `.232` 同一个）。首次访问会看到
   「首次使用，请设置管理员密码」是因为当时还没设；现在已设好。
3. **页面页脚显示 `v0.8.0`** —— `frontend/index.html:98` 的版本号是硬编码的，
   与实际 VERSION（0.19.19）不同步。**别拿页脚判断版本**。这个值得单独修。
4. **`.120` 的默认路由走 br-lan → 192.168.100.1**，而 WAN=eth1 有独立公网 IPv6。
   也就是说它是「LAN 侧接入 + 独立 WAN 口」的混合拓扑 —— 防火墙规则按
   WAN=eth1 / LAN=br-lan 生成是合理的，但**它不是网关**，LAN 设备的默认网关
   仍是 192.168.100.1。若打算让 .120 真正接管转发，需要改默认路由与
   LAN 侧网关指向。
5. 本次发现 `setup.sh` 的镜像 bug 只在**官方源不可用**时才会触发。
   本网络里官方源其实能用，所以之前几台机器没踩到 —— 但这不代表不会踩到。
