# 5443 面板的访问方式与反代要点

日期：2026-11-06
设备实测：`.232`（OpenWrt 25.12.5）
结论先行：**5443 面板保持内网直连，不做外网反代**（用户 2026-11-06 拍板，方案 C）。本文把定案依据与「将来若要外网化」的坑位固定下来，避免重复排查。

---

## 一、三个入口各是什么

| 入口 | 监听 | 用途 | 证书 |
|---|---|---|---|
| `https://192.168.100.232:5443` | **只绑 LAN IP**（不绑回环、不绑 0.0.0.0） | 面板本体，自带证书，不经过 nginx | `/etc/nginx/ssl/siyuan.fzyto.top/fullchain.pem`（自签） |
| `https://192.168.100.232:8443` | `0.0.0.0` + `[::]` | 认证网关：认证 + host/path 分发；`/` 是门户，`/fw/` 是面板入口 | 同上（同一张） |
| `127.0.0.1:8444` | 只绑回环 | 认证服务（网关的 auth_request 上游） | 无 |

实测（2026-11-06）：5443 直连 HTTP 200、8443 `/fw/` HTTP 200、8443 `/` HTTP 200。

### 面板为什么只绑 LAN IP

`backend/app.py` 里 `_bind` 的取值顺序（`app.py:13358`）：

1. 环境变量 `NFTABLES_WEB_BIND`
2. 否则 `_lan_bind_address(lan_if)` —— 探测 lan 网卡**此刻实际持有**的 IPv4

⇒ 默认绑 `192.168.100.232`，**不绑 `127.0.0.1`**。
⇒ 由此推出一条硬约束：**任何反代到面板的 upstream 都不能写 `127.0.0.1:5443`**，
即使反代 nginx 就跑在 `.232` 本机也不行。设备上现成的 `/fw/` 规则写的是
`proxy_pass https://192.168.100.232:5443/`，就是这个原因。

想让它绑全地址可以设 `NFTABLES_WEB_BIND=0.0.0.0`，但那会把面板暴露到所有网卡
（含可能的 WAN），与「面板仅 LAN、公网入口由网关端口承担」的设计相悖。

## 二、面板启动时自己打的说明

```
* HTTPS 主服务  : https://192.168.100.232:5443  (证书: /etc/nginx/ssl/siyuan.fzyto.top/fullchain.pem)
* 绑定来源      : <探测到的 LAN 地址>
* 访问范围      : 仅 LAN（公网入口由独立网关端口承担，见 gateway_port 配置）
* Cookie Secure : True（仅 HTTPS 传输，防 cookie 窃取）
```

`setup/setup.sh` 里也是同一句话：「面板本体直连 HTTPS 5443，自带证书，不经过 nginx」。

⇒ **反代不是 5443 能用的前提**。不反代就是内网控制台，跟项目早期完全一样。

## 三、「开关」有两个，别混

### 开关一：反代规则的「启用这条服务」

`backend/app.py:1974` 生成 nginx 规则时对 `enabled` 为假的规则直接 `continue`
⇒ 禁用后**网关配置里不写那个 location**，访问该路径得到 404。

设备上 `rp_002`「防火墙控制」现在 `enabled = True`，对应 `location /fw/`。

### 开关二：防火墙 LAN 放行端口

`lan_allowed_ports = [22, 5443]`（设备实况）⇒ 防火墙 input 链放行 LAN 方向的 22 与 5443。

### 结论

| 想干什么 | 依赖哪个 |
|---|---|
| 内网直连 `https://192.168.100.232:5443` | **不需要任何开关**（防火墙默认放行 + 只绑 LAN + 来源白名单兜底） |
| 从门户进面板 `https://192.168.100.232:8443/fw/` | 依赖开关一（反代规则 enabled） |

**把开关一关掉，只是 8443 上的 `/fw/` 入口没了，5443 端口本身照旧可达。**

> 若想让 5443 直连彻底关闭，要改的是 `lan_allowed_ports`（去掉 5443），不是点那个「启用这条服务」。
> 由此推论（**未实测**）：网关 nginx → 面板是**本机发起**的连接，走 output 链，
> 不受 input 链的 LAN 放行约束，所以 `/fw/` 入口理论上仍通。两个开关是一对，别只关一半。

## 四、证书这件事，实测结论与直觉相反

### 实测数据

```
5443:  subject=CN=siyuan.fzyto.top  issuer=CN=siyuan.fzyto.top   ← issuer==subject ⇒ 自签
8443:  subject=CN=siyuan.fzyto.top  issuer=CN=siyuan.fzyto.top
有效期: 2026-10-31 ~ 2027-10-31
不带 -k 时 curl 直接拒：HTTP=000
```

5443 与 8443 **共用同一张自签证书**。

### 为什么 5443 的自签证书不阻碍反代

- 浏览器只校验**它直连那一跳**（反代 nginx 对外的证书）。
- 上游 5443 的证书由 **nginx** 校验，不是浏览器。
- nginx 的 `proxy_ssl_verify` **默认 off**。

⇒ 实证：设备上 `location /fw/ { proxy_pass https://192.168.100.232:5443/; }`
**一个 `proxy_ssl_*` 都没写**，实测 `HTTP=200`、177558 字节 —— 已经在跑「nginx 反代到自签上游」。

### 那「网页不安全」是谁造成的

**反代那侧对外暴露的证书。**

- 直连 5443 报不安全 ⇒ 是因为上面那张自签证书，与反代无关。
- 反代出去后，若反代机器对外也用自签证书 ⇒ **一样报不安全**。

**判定标准只有一句：反代机器对「对外域名」有没有一张浏览器信任的正式证书。**
跟 5443 用什么证书无关。

## 五、真要外网化时的坑位清单

按踩坑难度排序。

### 1. upstream 不能写 `127.0.0.1:5443`
见第一节。写 `https://192.168.100.232:5443`。

### 2. 跨机反代 ⇒ 来源白名单会拒
`app.py:2735` 的 `_client_ip()`：**只在 `request.remote_addr` 是回环时才采信 `X-Real-IP`**，
否则一律用 `remote_addr`（不可伪造）。

⇒ 反代在别的机器上时，面板看到的来源是**反代机的 IP**，不是访客 IP。
⇒ 反代机必须在 `panel_allowed_nets` / `lan_subnet4` 里，否则回 `IP_NOT_ALLOWED`。
⇒ 额外放行用环境变量 `NFTABLES_WEB_PANEL_ALLOWED_NETS`（与配置取并集，不是收紧）。

来源边界的优先级（`app.py:576` 起）：
1. 配置显式 `panel_allowed_nets`
2. 配置文件存在且未损坏 → `lan_subnet4`
3. 配置缺失/损坏 → **不限制**（P1-26 的 fail-open），但会在
   `/api/auth/status` 的 `access_boundary_warning` 暴露，UI 有醒目告警

### 3. 对外端口必须是 80 / 443 / 8443 之一
`auth_gateway.py:2254` 的 `_origin_host_mismatch()`：允许端口 = {80, 443} ∪ {`gateway_port`(8443)}。

⇒ 别的端口（5443、8444…）⇒ 登录 403 `BAD_ORIGIN`。
⇒ 代码注释写明了原因：浏览器的同源策略按 scheme + host + **port** 算，
同主机不同端口是两个不同的源。

### 4. 域名要在白名单里
`auth_gateway.py:2211` 的 `_trusted_host_names()` 只认三处：
`reverse_proxy.settings.base_domain`、`reverse_proxy.settings.cookie_domain`、每条规则的 `host`。

设备实况：`base_domain = siyuan.fzyto.top`、`cookie_domain = .siyuan.fzyto.top`。

⇒ **子域自动放行**（`host.endswith("." + trusted)`）⇒ `panel.siyuan.fzyto.top` 可以。
⇒ **完全无关的域名**必须在面板「反向代理」里加一条 host 规则，否则 Origin 判跨站 ⇒ 登录 403。

### 5. 必须 HTTPS
`app.py:166-170`：`SESSION_COOKIE_SECURE = True`、`HTTPONLY = True`、`SAMESITE = 'Lax'`。

⇒ 反代走 http，浏览器直接拒收 cookie ⇒ 登录进不去。
⇒ `SameSite=Lax` 下同站登录 POST 正常。

### 6. `X-Forwarded-Proto $scheme` 一定要带
TLS 在反代这边终结，转给面板的已经是明文 HTTP ⇒ 缺这行 `request.is_secure` 恒为 False，
HSTS 永远不下发。网关每条 location 都写了这一行。

### 7. 上游 TLS 校验
上游是自签 ⇒ 保持 nginx 默认 `proxy_ssl_verify off` 即可。
若要开校验，三行必须齐：

```nginx
proxy_ssl_server_name on;
proxy_ssl_name siyuan.fzyto.top;
proxy_ssl_trusted_certificate /etc/nginx/ssl/siyuan.fzyto.top/fullchain.pem;
```

### 8. 上传体积
面板 `MAX_CONTENT_LENGTH = 16MB`（`app.py:172`）⇒ 反代的 `client_max_body_size` 要 ≥ 16m。

### 9. 子路径反代是支持的（不是只能根路径）
项目自己实现了子路径反代，两个开关：

- `api_path_prefix`（**窄模式**）：把这一段字面量替换掉，如 `'/api/'` → `'/fw/api/'`
- `rewrite_root_paths`（**宽模式**）：替换「HTML 属性值紧跟」的根绝对路径，
  如 `href="/x"` → `href="/fw/x"`、`src="/x"`、`action="/x"`、`url('/x')`

再配 `proxy_redirect` 给 302 的 Location 补回前缀。

设备上 `rp_002` 就是 `api_path_prefix='/api/'` + `rewrite_root_paths=True`，**跑通了**。

> 这条纠正过一个说法：「必须根路径反代，子路径会 404」——不准确。
> 子路径要开上面两个开关，否则前端吐的根绝对路径资源会跑出该 location 导致 404。

## 六、可直接用的反代配置模板

```nginx
server {
    listen 443 ssl;
    server_name panel.siyuan.fzyto.top;          # ← 你的对外域名

    # ★ 必须是浏览器信任的正式证书；自签的话浏览器照样报「不安全」
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass https://192.168.100.232:5443;   # ← 不能写 127.0.0.1:5443

        # 上游是自签 ⇒ 保持 nginx 默认 proxy_ssl_verify off 即可
        # proxy_ssl_server_name on;
        # proxy_ssl_name siyuan.fzyto.top;
        # proxy_ssl_trusted_certificate /etc/nginx/ssl/siyuan.fzyto.top/fullchain.pem;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;   # ★ 不带这行 HSTS 不下发

        client_max_body_size 16m;                      # 面板上限 16MB
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_http_version 1.1;
    }
}
```

子路径版（`/panel/`）还需要加上设备上 `/fw/` 那套 `sub_filter` + `proxy_redirect`，
可直接照抄 `/etc/nginx/conf.d/00-nftables-web-gateway.conf` 里 `location /fw/` 那一段。

## 七、最终决定与最短路径

**决定（2026-11-06，用户拍板）**：5443 保持内网直连，不做外网反代。**零改动。**

将来若要让门户 8443 对外访问且浏览器不报「不安全」，最短路径是
**把 `siyuan.fzyto.top` 那张自签换成正式签发的**（5443 与 8443 共用 `/etc/nginx/ssl/siyuan.fzyto.top/`，
换一张两个入口一起干净；项目已集成 acme.sh，续期带 `--reloadcmd nginx -s reload`）。

⚠️ **前提**：签发前必须确认 `siyuan.fzyto.top` 当前解析到哪台机。
若指向现网 `.1`，HTTP-01 验证会直接打到现网 —— 属于禁止操作，需改用 DNS-01，
或由用户另行明确授权。
