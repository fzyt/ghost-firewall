# 网关访客页 + 白名单时效分离（2026-11-18）

## 这批做什么

用户提了两件事：

1. **设备指纹单独能看**：现在指纹只能在日志里翻，想做一个能按指纹看
   「这是哪个 IP、访问了哪些服务、什么时候」的页面。
2. **最近访问网关端口的 IP 列表**：能快速筛选，右边点一下就能加白名单；
   加白名单的时效**与端口敲门的时效分开**，可自定义，默认 10 分钟。

本报告覆盖第 2 件事（访客页 + 时效分离）的完整落地。第 1 件事（设备指纹页）
是下一批，它复用本批建好的「访客聚合」这套读法。

## 需求确认与取舍

动手前用问卷确认了两处会改变实现的地方：

| 岔路 | 选了什么 | 为什么 |
|---|---|---|
| 时效分离做到哪一层 | **彻底版**：名单落盘带超时，重建规则后仍保持 10 分钟 | 轻量版有个坑：点「应用规则」后 10 分钟会悄悄变回 5 小时 |
| 设备页要不要关联网关的 nginx 访问记录 | **关联** | 审计日志只有路径，关联网关日志才有服务域名、状态码、UA |

「加白名单」加的是 `allowed4`/`allowed6`，效果是**免敲门放行**，
**不等于免登录** —— 网关的认证那道闸一点没松。这点在页面上写明了。

## 核心：时效分离为什么不是「加个配置项」就行

这套白名单里有**两套时效**，原本混在一起：

- **敲门那套**（`whitelist_timeout`，设备上实测 1 小时）：敲门成功后，
  该 IP 免敲门多久。走的是 nft set 的**默认** timeout。
- **手动加那套**（本批新增 `manual_whitelist_timeout`，默认 600 秒 = 10 分钟）：
  用户在访客页点一下加白名单，为了「临时放行一下」。
  走的是 nft 的**元素级** timeout：`nft add element ... { ip timeout 600s }`。

坑在这里：**元素级 timeout 只存在内核里**。名单文件（`lists.json`）落盘的是
**裸 IP** ⇒ 一旦点「应用规则」重建整个 set，回填的是裸 IP ⇒ 元素级 timeout
丢失 ⇒ 用户手动加的「10 分钟」悄悄变回敲门的 1 小时（出厂默认 5 小时）。

所以「时效分离」必须做到**落盘也带得上**，否则只是**看着分离**。

### 本批的做法：名单文件格式不变，时效另存一处

| 东西 | 存在哪 | 为什么这么放 |
|---|---|---|
| 名单成员 | `lists.json`（`allowed4` / `allowed6` / …），**格式一字未改** | 老设备升级零风险，不需要做数据迁移 |
| 元素级时效 | config 的 `whitelist_ttls`：`{"1.2.3.4": 600}` | 与名单解耦，名单文件保持人可读的纯 IP |
| 渲染 | 渲染前把两者合成 `1.2.3.4 timeout 600s` 这个**中间形态** | 渲染层只认一种写法 |

中间形态由 `template_engine.split_list_elem()` 拆解，
它同时是**注入面**的闸门：timeout 子句会被原样拼进 nft 规则文本，
而规则集文件是 `nft -f` 执行的 ⇒ 解析不出来就**整个元素丢弃**，
绝不「尽力而为」放行。

已拒的形态（判据逐条覆盖）：`timeout 0s`、`timeout 999999999s`（超上限）、
`timeout 60m`（元素级只认秒）、`timeout 600s drop`（多出一截）、
`timeout １s`（全角数字 —— `str.isdigit()` 对 Unicode 数字返回 True，
`int()` 会把它悄悄转成 1）、以及各种 `; delete table inet fw4` 注入形态。

## 访客页读什么

数据源是网关自己的 nginx 访问日志（`/var/log/nginx/nftables-web-gateway.access.log`）——
**不是另记一份**，数据已经在采，再记一份就是两个真相源。

日志格式由本项目生成 nginx 配置时定死：

```
$time_iso8601 $remote_addr $request_method $status $body_bytes_sent rt=$request_time
host="..." uri="..." ua="..." ref="..." auth_user="..." auth_dev="..."
```

按 IP 聚合出：次数、首次/最近访问时间、访问过的服务域名（`host`）、
路径（`uri`）、状态码、UA、设备 ID（`auth_dev`），并附上该 IP 当前的
白名单状态与剩余时效。

`auth_dev`（nginx 侧）≡ 审计日志的 `device` ⇒ 下一批的设备指纹页就是靠这个
把「认证指纹」和「访问记录」对上的。

### 时效分离（本批最核心的一条）

加白名单 `203.0.113.77`、时效 600 秒后，看**真实内核 set**：

```
set allowed4 {
    type ipv4_addr
    flags dynamic,timeout
    timeout 1h                                    ← set 默认（敲门那套）
    elements = { 203.0.113.77 timeout 10m expires 9m59s980ms }   ← 元素级（手动加的）
}
```

- 元素带的是 **10 分钟**（nft 把 600 秒规范化显示成 `10m`），
  且有真实的剩余时间 `expires` ⇒ 元素级 timeout 确实生效。
- 与 set 默认的 `1h` **明确不同** ⇒ 两套时效确实分离。

### 「点应用规则」用的那份文本

```
规则文本：elements = { 203.0.113.77 timeout 600s }
nft -c -f - 语法预检：返回码 0
规则集文件（设备重启加载的就是它）：elements = { 203.0.113.77 timeout 600s }
```

⇒ 重建 set 之后仍然是 10 分钟，**不会退回敲门那套**；设备重启后仍然有效。

### 名单文件格式不变

```json
{ "allowed4": ["203.0.113.77"], "allowed6": [], "blacklist4": [], "blacklist6": [] }
```

仍是裸 IP，没有 timeout 子句 ⇒ 老设备升级零风险、不需要迁移。
时效另存在 config：`{"203.0.113.77": 600}`。

验证用完已清理：内核 set、config、名单文件里都没有测试 IP 残留。

### 真机截图抓到的 UI 缺陷（已修）

第一版截图里，「观察窗口」下拉框显示的是**「最近 15 分钟」**，而状态值是
**60**（应为「最近 1 小时」）—— 界面与实际值不一致。

根因：option 的 value 写成了 `:value="60"` 这种**动态绑定**。Alpine 初始化
`x-model` 时是**父先子后**遍历的（`select` 先于它的 `option`）⇒ 那一刻
option 还没有 `value` 属性 ⇒ 浏览器拿 option 的**文本内容**当 value
（「最近 15 分钟」）⇒ model 值 60 匹配不上任何一项 ⇒ 下拉框回落到第一项。

修法：option 改用**静态** `value="60"`（Alpine 3 的标准用法；`x-model.number`
负责把字符串转成数字）。已加前端判据 + 变异 V-28 守着这条。

顺带一个坑：验证脚本里**不能**用 CSS 属性选择器找这个 select ——
`'x-model.number'` 里的点号在 CSS 语法里非法，`querySelector` 会直接抛
`DOMException`。只能遍历 `select` 列表比对 `getAttribute('x-model.number')`。

## 顺带挖出并修掉的七个真问题

这七个都不是本批功能本身的问题，但都是**真问题**，一并修了。

前四个是**上一批**留下的坑（第四章是本批自己造的），后三个是本批回归期间挖出来的。

### 一、`mutation_check_functional.py` 的 FIX-11 锚点失配（静默失效）

改动 `list_add` 的 nft 调用形态后，FIX-11 的 old 锚点不再命中。
该脚本对「锚点出现 0 次」的处理是**跳过**（不计入漏网）⇒
那条变异一直**没跑过**，而脚本仍然报 rc=0 ⇒ 守门形同虚设。

修法：更新锚点到新形态；并修好了下面那个体检工具，让这类问题几秒内可见。

### 二、锚点体检工具自己有两个洞（`tests/test_mutation_anchors.py`）

这个工具是上一批加的，本批在它身上挖出两个洞：

| 洞 | 后果 | 修法 |
|---|---|---|
| 只认 **2 元组**的变异锚点 | 5 元组脚本（functional / portal_frontend / fw_recovery / iface_pin）**一条锚点都没被体检过** | old 统一取 `elts[-2]`，覆盖 2/3/4/5 元组 |
| `looks_like_code` 要求 `'\n' in s` | **所有单行锚点**被排除在外 —— 而单行锚点恰恰最容易因为上游改一行就失配 | 放宽为「含代码符号即算」 |

外加一处：`resolve_target_files` 只认顶层 `Assign`，认不到 `FILES = {...}`
映射表里的路径 ⇒ 那些脚本的锚点被误判成「在错的地方」。

**修完之后体检覆盖面从 203 条锚点涨到 807 条**（4 倍），63 个脚本全命中。

⚠ 但这仍然不够 —— 见第四章：命名常量锚点与两种特殊形态**仍未被覆盖**，
最终在本轮涨到 **883 条**。

### 三、nginx 访问日志的「字符交织」坏行

真机日志里抓到过这样一行：

```
2026-11-18T18:38:58+08:00 192.168.100.gzl GET 200 2764 rt=0.001 host="192.168.100.193" ...
```

IP 变成了 `192.168.100.gzl` —— nginx 的 access_log 是**多个 worker 追加写**的，
偶发会写出字符交织的半截行。而正则照样能把它当 IP 收下 ⇒
访客列表里会出现一条**根本不存在**的访客。

修法：IP 必须是真 IP（`ipaddress.ip_address` 判一下），不合法就**整行跳过**
（那一行的来源地址已经不可信了）。

### 四、本批自己把守门守没了（第一轮回合一小时才发现）

前面三个问题都是**上一批**留下的坑。第四个是**本批自己造的**：

改 `_format_list_elements` 和 `template_engine._inject_list_elements` 时，
顺手调了这两处 `if '%' in ...` 后面注释的**缩进空格**（6 个 → 4 个）。
而 `mutation_check_c2_c3_c4.py` 的 M14~M17 四条变异，其 old 锚点正是
**照抄这两段源码**（含那几行注释）⇒ 锚点立刻失配。

后果有两层：

1. 那四条变异**根本没跑过**（脚本前置闸门直接 rc=2 退出）。
2. 第一轮完整回归跑了**一小时**，日志里只留下一行
   `❌ mutation_check_c2_c3_c4.py` —— **后面什么字都没有**。

第 2 点才是真正要命的：`run_all.sh` 的失败详情过滤器只认 `❌` 和 `⚠️`，
而变异脚本的失败行用的是 `[FAIL]` 纯文本（项目禁用 emoji）⇒ 匹配不到
⇒ **失败原因被吞掉**。

⇒ 也就是说：一个「锚点失配」本来该几秒钟查出来（体检工具就是干这个的），
结果因为体检工具有洞（见第二章的遗留）＋ 回归日志吞原因，
硬生生拖成**一小时的满负荷回归**，还只得到一行空白。

本轮三处修法：

| 位置 | 修法 | 效果 |
|---|---|---|
| `tests/mutation_check_c2_c3_c4.py` | 从当前源码**程序化重建**两条锚点常量（不手抄，避免再抄错空格） | 17/17 变异全捕获，rc=0 |
| `tests/test_mutation_anchors.py` | 认**命名常量**锚点（`_resolve_str`）＋ 认特殊形态（`_resolve_alt_shape`：lambda 里的 `s.replace()`、四元组 `(old,new,nth,count)`） | 体检覆盖 **807 → 883 条** |
| `tests/run_all.sh` | 失败详情过滤器加 `[FAIL]`，匹配不到就退而打印输出尾部 | 失败原因直接进日志 |

其中体检工具那两处最关键：**此前 13 个脚本、65 条锚点从未被体检过**
（命名常量在 AST 里是 `ast.Name`，旧版只认 `ast.Constant`），
而工具照样报「全部通过」。`mutation_check_security.py` 的后果尤其隐蔽 ——
它的变异是 `s.replace(...)`，模式没匹配上时 `mutated == original`
⇒ 脚本**跳过**这条变异 ⇒ 看起来绿，其实那条变异从没跑过。

反向验证过：故意把一条命名常量锚点改坏 ⇒ 体检**立刻**报错并指出是哪一条；
改回来 ⇒ 全绿。**0.3 秒取代一小时**，这正是这个工具存在的意义。

### 五、保险丝把文档改动也吞了（本批新发现，回归期间踩到）

回归运行期间我在 `报告/` 里补文档，脚本退出后**内容被还原了**。

根因在 `tests/_mutation_guard.py`：它的 `_tracked()` 用 `git ls-files` 取
**全部**跟踪文件做快照 —— 包括 `报告/`、`README.md`、`CHANGELOG.md`。
而变异脚本只改源码（`backend/ frontend/ setup/ tools/`），
**文档目录根本不该进快照**。

更隐蔽的是：回归收尾的源码指纹对账只覆盖
`backend/ frontend/ setup/ tests/ docker/` ⇒ **不含报告目录**
⇒ 连对账都发现不了这次丢失。

修法：快照范围限定为源码目录（`SOURCE_DIRS`）⇒ 文档不再进快照。
判据：`tests/test_mutation_guard_concurrent_edit.py` 第 5 节（19 条断言，
走**真实** `snapshot()` 路径）。

> ⚠ 判据的首版自己写错了：手工往快照目录里塞文档文件，**绕过了**
>   `_tracked()` 过滤 ⇒ 测的是假场景 ⇒ 判据自己报了假失败。
>   改成「建真 git 仓库、让 `git ls-files` 能列出文档」才测到真实行为。

实证：在报告里写了个探针，让 6 个变异脚本依次跑完（每个退出时都会调
`restore()`）⇒ 探针**完好无损** ⇒ 修复确实生效。

### 六、防线变多 ⇒ 旧变异变成等价变异（第三轮回归才发现）

本批给名单元素加了「IP timeout Ns」形态 ⇒ `template_engine._inject_list_elements`
里长出了**新的第一道关卡**（`split_list_elem` 拦截）。

而 `tests/mutation_check.py` 的复合变异「名单元素的两道防线同时拆掉」，
拆的是 `except ValueError` 那一道 ⇒ **拆了也破坏不了**
（前面那道已经拦住了）⇒ 变异退化成等价变异 ⇒ 判成漏网
⇒ 第三轮回归 `捕获 21 / 22`。

脚本自己的注释早就写明了这条规律：「防线的数量变了，变异脚本必须跟着变」。

修法：改成**整个校验块一起拆**（所有子防线同时失效）——
以后再加防线也不必再改这个脚本。

> 踩坑：第一次改的时候只拆了 `except` 那一块，**忘了后面的
> `if (addr.version == 6) != want6:` 还要用 `addr`** ⇒ 变体代码 NameError
> ⇒ 测试脚本**崩溃** ⇒ 判据只认断言失败行、不认崩溃 ⇒ 仍然判成漏网。
> ⇒ 变异必须**能跑**：拆的时候要把整块连着后面的引用一起处理。

### 七、一条「在测机器」的断言，负载一高就假红

`tests/test_p0_security_fixes.py` 里有一条断言：*dummy 路径耗时 ≥ 真实路径*
（防的是攻击者靠响应时间区分「配了密码 / 没配密码」）。

它用 `time.process_time()` + 3 次取最小值，脚本注释里还记着同类历史
（「换 process_time 后 40 次里 1 次假红」）。

但在本批的快速回归里它**还是红了**：真实=127.3ms、dummy=102.2ms（0.80x）。
单独连跑三次却全绿（0.96x / 1.03x / 1.04x）⇒ **机器负载导致的抖动**，
与本批改动无关。

⇒ 治本的办法不是「多采几次」，而是**别拿耗时当判据**：
耗时受 CPU 频率、缓存争用、调度影响，测的是机器不是代码。

改成**确定性**断言：拦 `hashlib.pbkdf2_hmac` 记录两条路径**实际用了多少轮迭代**，
直接比对「dummy 轮数 ≥ 真实轮数」。这才是「dummy 不慢于真实」的**成因**
（轮数相同 ⇒ 耗时必然相同）。

反向验证过：把 `PBKDF2_ITERATIONS_DUMMY` 从 200000 改成 1000 ⇒
新判据立刻报出「真实=200000 轮，dummy=1000 轮」⇒ **有鉴别力**，
而且比旧的耗时判据更强（一眼看出轮数不对，不用等耗时差显现）。

## 限制与已知边界

1. **只覆盖网关 8443 的 HTTP 访问**。不含：面板 5443、LuCI 80/443、
   只建 TCP 连接没发 HTTP 请求的、以及被 nft 挡在防火墙外面的包。
2. **访问日志只增不减**。设备实测：`/var` 在 tmpfs 上（492MB），
   且 OpenWrt 上**没有 logrotate** ⇒ 这份日志不轮转。
   本批做的是「**只读文件尾部 512 KiB**」让**面板的内存**有界，
   但**文件本身仍会涨**。要根治得装 logrotate 或改到持久化路径 ——
   那是引入新依赖/改部署，超出本批范围，**留给用户决定**。
3. **「加白名单」= 免敲门放行，不是免登录**。网关的认证那道闸一点没松。
4. 时效只对**白名单**有效。黑名单的 nft set 是 `flags dynamic`（**没有**
   timeout 标志），带 timeout 的元素 nft 会拒收 ⇒ 后端提前拒掉并说明原因。
5. 访客列表默认只看最近 1 小时，最长 7 天，单次最多返回 500 个 IP。
