# 变异回归防线被自己的注释顶破 —— M20 漏网的定位与加固

日期：2026-11-05
关联提交：`40bf052`（v0.19.3）、`0bb4006`（本次加固）
关联报告：`报告/apk三缺陷真机验证-2026-11-05.md`

---

## 一、现象

v0.19.3 落地后跑变异脚本，`mutation_check_setup_resume.py` 报：

```
❌ M20 pkg_install_apk 不走本地文件兜底（大包一失败就永久卡住）  —— 漏网！测试没抓住
════════ 结果：捕获 34 / 35 ════════
```

对照上一轮提交 `5739ed6`（同样的脚本、同一台机器、同一套依赖）：

```
════════ 结果：捕获 35 / 35 ════════
```

⇒ **M20 漏网是 v0.19.3 这一轮引入的，不是历史遗留。**

这条变异的含义：把 `pkg_install_apk` 里「apk 装不上时改走本地文件兜底」这一段去掉。
漏网 = 未来真有人把兜底删了，**没有任何测试会变红**，而真机上「大包一失败就永久卡住」
正是当初加兜底要解决的问题。

---

## 二、根因：注释里写了函数名，把断言顶住了

M20 的变异是把 `setup/setup.sh` 里这一行

```sh
    if apk_install_via_local_file "$pkg"; then
```

换成 `if false; then`（让兜底永不触发）。

而测试 `tests/test_setup_resume.py` 里的断言是：

```python
pia = fn_body(setup, 'pkg_install_apk')
check('pkg_install_apk 重试耗尽后会走本地文件兜底',
      'apk_install_via_local_file' in pia)
```

`fn_body` 切出来的是**带注释**的函数体。

而 v0.19.3 为了把真机事实记进代码，恰好在这个函数里加了一句注释：

```sh
    #   （实测细节见 apk_install_via_local_file 上方的说明）：apk-tools 3.0.5
```

⇒ 真实调用被换掉了，但注释里**同一个字符串还在** ⇒
`'apk_install_via_local_file' in pia` 依然成立 ⇒ 断言照样通过 ⇒ 变异漏网。

**一句话**：上一轮为了把真机事实记进代码而加的注释，恰好把自己的回归防线顶掉了。

这不是笔误，是一类结构性隐患的实例：
**断言问的是「代码里有没有这个东西」，但它拿到的是「代码 + 注释」。**
注释里只要出现过一次目标字符串，断言就再也挡不住「把代码改掉」的变异。

## 三、修法

| # | 改法 | 位置 |
|---|---|---|
| 1 | `fn_body` 默认去掉整行注释（`strip=False` 可要原文） | `tests/test_setup_resume.py` |
| 2 | 全文结构断言改查 `setup_code`（去注释版）；只有「连注释里也不许有这句老逻辑」那一条仍查全文 `setup_full` | 同上 |
| 3 | 分支切分的结束锚点从注释（`# GitHub 安装`）换成代码（`local tag=`）——去注释后注释锚点会消失 | 同上 |
| 4 | 「兜底安装前会校验包头」同样改查去注释版 | `tests/test_setup_apk_fallback.py` |

复验：同一份变异脚本在独立副本里跑，回到 **捕获 35 / 35**。

### 为什么不全改成「一律查去注释版」

有一类断言要的就是「连注释里也不许有这句话」
（第 4 节的「不再有『非交互模式就跳过项目部署』的老逻辑」）。
那种必须查**全文**。所以这里是**分流**而不是一刀切：
「应该存在」查去注释版，「不应该存在」查全文。

## 五、另一类隐患：锚点缩进漂移（从 v0.19.2 起就有）

`tests/mutation_check_config_ownership.py` 的两条版本闸变异，
**从 v0.19.2 起就一直没在跑**：

```python
# 旧锚点（8 空格）
"        if sent_rev != cur_rev:",
# 现行锚点（4 空格）
"    if sent_rev != cur_rev:",
```

原因：v0.19.2 的 P1-24 把版本闸从「嵌套在 if 里」改成「函数体层级 + 提前 return」，
缩进从 8 空格变成 4 空格，锚点却没跟着改。

脚本的行为是「锚点未命中 → 报错跳过」，返回码 1。
**但那行没人看** ⇒ 变异静默不生效 ⇒ 而「未生效」极容易被当成「通过」。

修正锚点后单独复跑：`变异 11 处  捕获 11  锚点未命中 0`。

> **教训**：变异脚本的「锚点未命中」必须当成**失败**看待。
> 少跑一条 = 那条缺陷从此没人守，哪怕「捕获数看起来对得上」。

## 六、本轮全仓变异扫描（修正统计口径后）

统计口径踩过一个坑，先记在这里：

**`↩` 开头的行有两类，不能混。**

- `↩ 已还原 backend/app.py` —— **还原提示**，每条变异还原一次都会打一行
- `↩ 跳过 ...` —— 真正的跳过，那条变异根本没跑

早先只按 `↩` 前缀判跳过 ⇒ 把 30 条还原提示误报成「30 条变异没跑」，
总数也因此被虚报成 648。修正后：

| 项 | 数值 |
|---|---|
| 变异脚本 | 36 个（门户脚本 223 条另算，见下） |
| 变异总数 | 618 |
| 捕获 | 618 |
| 漏网 | 0 |
| 锚点未命中 | 0 |
| 真跳过 | 0 |
| 门户脚本（`mutation_check_portal_frontend.py`） | 223 条，捕获 223，漏网 0（6 份独立副本跑完） |

另有 2 条**等价变异**被脚本自己标注不算漏过（`mutation_check_auth_hardening.py`）：

| 变异 | 理由 |
|---|---|
| Flask：删掉读之前的 `content_length` 前置检查 | 等价 —— `except RequestEntityTooLarge` 分支会兜住同样的请求 |
| Flask：删掉 `RequestEntityTooLarge` 分支 | 等价 —— `content_length` 前置检查先拦下，实测仍返回 413 |

这两条是有意的**双保险**设计，单独删掉一个确实等价，判断正确，不是覆盖漏洞。

## 七、并发下的一个观察

36 个脚本 6 并发跑时，`mutation_check_p0_fixes.py` 在**第一轮**退出码非 0（标 BAD），
但它自己的报告是「变异 25 处  捕获 25  漏过 0」。

单独在干净副本里复跑：**退出码 0，25 处全捕获**。
第二轮同样 6 并发，该脚本也正常（退出码 0、25 处全捕获）。

⇒ BAD 是**并发环境下的间歇性资源竞争**（端口/超时），不是漏网。
这类噪声会让「退出码」这个信号变脏，判定时应以脚本自己的「捕获/漏网」计数为准，
并对 BAD 项单独复核。

### 关于「断言合计」这个指标

`run_all.sh` 的注释里记着一段历史：早期统计用 `[0-9]+/[0-9]+` 排除整文件汇总行，
结果**断言总数会随随机临时目录名而变**（实测同一份代码两次跑出 1408 / 1410）。
2026-11-03 改成行首锚定后这个问题解决了，本轮两遍复跑确认数字稳定。

另有一个**已知的虚高**：`test_setup_apk_fallback.py` 的结尾汇总行
`✅ 通过 44 / 44` 行首就是 ✅ ⇒ 被计入 ⇒ 该文件显示 45，真实断言数是 44。
不影响正确性（只多不少），但看单文件数字时要知道这一层。

## 九、方法论沉淀

1. **注释不是无害的**。往源码里加一句「背景说明」，可能正好把某条回归防线顶破。
   断言要在代码里找东西，就不能让它看见注释。
2. **「锚点未命中」不是噪声，是覆盖漏洞**。少跑一条变异 = 那条缺陷从此没人守。
3. **变异脚本自己的计数才是权威**，退出码会被并发噪声污染。
4. **还原提示 ≠ 跳过**。统计口径里的每一类行都要单独确认，否则会把「全过」误读成「没跑」。
5. **加注释和加断言会互相影响**。改源码时要看一眼：这句话会不会出现在某条断言的目标字符串里。
