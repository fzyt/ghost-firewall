# 门户「防火墙控制」卡片 —— 端到端验证步骤与验收点

> 2026-11-04 第十五轮
> 目标：验证门户登录后点开「防火墙控制」卡片，能否一路走到防火墙控制界面。
> 测试机：`192.168.100.232`（用户授权的测试机，非现网）

---

## 一、验证环境

| 项 | 值 |
|---|---|
| 门户地址 | `https://192.168.100.232:8443/` |
| 面板直连 | `https://192.168.100.232:5443/`（只绑 LAN IP） |
| 反代规则 | `rp_002` → 路径前缀 `/fw`，`icon=FW`，`public_access=false`（仅内网） |
| 路径改写 | `api_path_prefix=/api/`、`rewrite_root_paths=true` |
| 部署版本 | v0.18.0（`6c980de`） |

⚠️ **不要碰 `192.168.100.1`**（`ces.fzyto.top` 的解析目标，正式在用版本）。

## 二、操作步骤

### 步骤 1 — 打开门户并登录

浏览器访问 `https://192.168.100.232:8443/`

- 证书是自签 ⇒ 浏览器会拦 ⇒ 点「高级」→「继续前往」
- 填门户密码，提交

**验收点 1.1**：登录后进入门户卡片页，背景是像素场（不是纯色）
**验收点 1.2**：页面左上角显示当前用户，右侧有「退出」按钮

### 步骤 2 — 找到「防火墙控制」卡片

在卡片列表里找**图标是 `FW`、名字是「防火墙控制」**的那张。

**验收点 2.1**：卡片存在，图标显示 `FW`（不是路径首字母 `/`）
**验收点 2.2**：卡片副标题显示 `/fw`
**验收点 2.3**：卡片右下角标签是「**仅内网**」（不是「公网 · 需认证」）

> 同时应该能看到「思源-测试」卡片（图标是路径首字母 `S`）——
> 两张卡片的图标不同，说明 icon 字段确实生效了。

### 步骤 3 — 点开卡片

鼠标按下卡片 → 松开。

**验收点 3.1**：按下瞬间卡片亮一下（`is-hit` 高亮）
**验收点 3.2**：出现「门关闭」动画，然后跳转到 `https://192.168.100.232:8443/fw/`
**验收点 3.3**：**地址栏仍然是 8443 端口**（没有跳到 5443，也没有跳到别的域名）

### 步骤 4 — 落到面板界面

**验收点 4.1**：看到管理面板界面（左侧栏 + 主内容区），不是 404 白屏
**验收点 4.2**：页面背景是像素场（`#nf-pix` 画布渲染出来了）
**验收点 4.3**：打开浏览器 F12 → Network，看接口请求 URL 是 `https://192.168.100.232:8443/fw/api/...`（**带 `/fw/` 前缀**），返回 200 不是 404
**验收点 4.4**：F12 → Console **没有红色报错**

### 步骤 5 — 在面板里做一次真实操作

进「规则」或「反代」页，看列表能否正常加载；点一次「刷新」。

**验收点 5.1**：列表有数据，不是空数组也不是转圈卡住
**验收点 5.2**：Network 里对应请求返回 200

### 步骤 6 — 退出登录

**验收点 6.1**：点「退出」后回到登录页
**验收点 6.2**：退出后直接再访问 `https://192.168.100.232:8443/fw/` ⇒ 应被弹回登录页或 401，**不能直接看到面板界面**

## 三、已知要提前说明的一点

**卡片点开后，面板会要求再输一次面板自己的密码**（面板登录遮罩）。

实测（2026-11-04）：

```
GET https://192.168.100.232:8443/fw/api/auth/status
→ {"data":{"authenticated":false,"password_set":true},"success":true}
```

原因：门户的登录态和面板的登录态是**两套**（网关 token vs 面板 session），
`/fw/` 只是把面板**反向代理**到网关的同一个端口下，并没有打通两套会话。

所以第 4 步落地时看到的是**面板的登录卡片**，
要先在面板这一层输一次密码，才看到真正的防火墙控制界面。

如果你要的是「门户登录一次 → 点开直接进控制台，不再问密码」，
那是 **SSO（免二次登录）**，第 15 轮问卷里你选的是「先不做」。

⇒ 本次验证只需在步骤 4 之后补一次面板登录即可，
   验收点 4.1 之后的内容都在面板登录之后进行。

## 四、出问题时的自查

```bash
# 门户 API 有没有返回 FW 卡片（内网来源免登录，直接从 .232 上查）
ssh root@192.168.100.232 \
  'curl -sk https://192.168.100.232:8443/auth/portal'

# /fw/ 反代链路通不通
ssh root@192.168.100.232 \
  'curl -sk -o /dev/null -w "fw=%{http_code}\n" https://127.0.0.1:8443/fw/'

# 面板自己通不通
ssh root@192.168.100.232 \
  'curl -sk -o /dev/null -w "panel=%{http_code}\n" https://192.168.100.232:5443/api/auth/status'

# nginx 的 /fw location 段
ssh root@192.168.100.232 \
  'sed -n "/location \/fw/,/^    }/p" /etc/nginx/conf.d/00-nftables-web-gateway.conf'
```

**已确认正常（2026-11-04 实测）**：

| 检查项 | 结果 |
|---|---|
| `GET /auth/portal` | 200，返回 `{"icon":"FW","name":"防火墙控制","path":"/fw","public":false,"url":"/fw/"}` |
| `GET /fw/` | 200，176KB HTML |
| `GET /fw/api/auth/status` | 200，`{"authenticated":false,...}` |
| `GET /fw/` 里的资源路径 | 已改写成 `/fw/assets/...`、`/fw/pixelfield.js`、`/fw/pixelbg.js` 等 |
| `GET /fw/api/auth/status`（未登录） | `authenticated=false` ⇒ 需要面板登录 |
